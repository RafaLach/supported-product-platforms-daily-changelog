## Platform Details

### ChatGPT Enterprise (OpenAI) — Codex CLI & SDKs

- **Codex CLI 0.136.0 (June 1, 2026) — native Amazon Bedrock backend**: The local Codex agent can now run against Amazon Bedrock with AWS-managed authentication (Bedrock API key via `AWS_BEARER_TOKEN_BEDROCK`/`AWS_REGION`, or the standard AWS SDK credential chain — `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN`, shared config, or console creds — with SigV4 signing). Same release also adds session archiving via the `/archive` command and Windows sandbox provisioning with an elevated setup path. Source: https://developers.openai.com/codex/amazon-bedrock
- **OpenAI Python v2.40.0 / Node v6.41.0 (June 1, 2026) — Amazon Bedrock Responses support**: The official SDKs add a first-class Bedrock client so the Responses API can be pointed at the `bedrock-mantle` OpenAI-compatible endpoint (`OPENAI_BASE_URL=https://bedrock-mantle.<region>.api.aws/v1`) authenticated with a Bedrock API key instead of an OpenAI key. The immediately prior releases (Python v2.39.0 / Node v6.40.0, also June 1) added workload identity in audit logs, additional tools in responses, and made `ActionSearch.query` optional. Source: https://developers.openai.com/api/docs/guides/amazon-bedrock

## New Coverage Required

- **[AIDR] [MEDIUM] OpenAI SDKs & Codex CLI add native Amazon Bedrock provider (cross-cloud inference routing)**: As of June 1, 2026, the official `openai-python` v2.40.0, `openai-node` v6.41.0, and Codex CLI 0.136.0 all ship turnkey "Amazon Bedrock Responses support," letting OpenAI's standard client libraries and the local Codex agent send Responses/Chat traffic to AWS Bedrock's OpenAI-compatible `bedrock-mantle` endpoint authenticated with AWS credentials (Bedrock API key or IAM/SigV4) rather than an `OPENAI_API_KEY`. The underlying OpenAI-on-Bedrock integration has been GA since April 2026, but moving it into the default SDKs and CLI makes it the path of least resistance and breaks several monitoring assumptions: detection keyed on "OpenAI SDK ⇒ api.openai.com" now misses inference that terminates at AWS Bedrock; a single OpenAI-shaped agent may straddle two monitored clouds; and a developer endpoint running Codex can hold AWS credentials and open a new egress path to `bedrock-mantle.*.api.aws`. AIDR should treat OpenAI-client / Codex traffic to the `bedrock-mantle` endpoint as a monitored cross-provider data flow (and attribute it to the OpenAI SDK rather than a generic AWS call), while ENDPOINT-side inventory should flag Codex installs configured with the `amazon-bedrock` model provider as holding AWS credentials with a Bedrock egress path. New toxic combination: a Codex endpoint with broad AWS IAM credentials plus the Bedrock provider can route prompt/response data — including injected instructions — into the customer's own AWS account, blending agent traffic with first-party AWS API activity. Source: https://developers.openai.com/codex/amazon-bedrock
