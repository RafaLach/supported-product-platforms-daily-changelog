## Platform Details

### Amazon Bedrock AgentCore

Source note: the following June 2026 items were captured from `https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html` (which renders fully) after the configured `doc-history.html` source again failed to render. Each was cross-checked against all prior reports and is net-new to the cache.

- **Managed Knowledge Base — GA** — a fully managed retrieval-augmented-generation (RAG) knowledge base that agents query through the Gateway as a pre-built target type. Six native connectors (Amazon S3, SharePoint, Confluence, Google Drive, OneDrive, Web Crawler) ingest data with automatic syncing and managed vector storage; supports hybrid search, document ranking, advanced retrieval orchestration, and text/video/audio/image content; auto-generates role-based permissions with observability/eval metrics. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/knowledge-base.html
- **Web Search Tool — GA** (announced AWS Summit New York, June 17, 2026) — a fully managed tool that grounds agent responses in current web knowledge with zero data egress from the customer's AWS environment, built on Amazon's web index + knowledge-graph data. Exposed as a built-in connector target on the AgentCore Gateway via MCP; returns ranked results with snippets, source URLs, titles, and publication dates. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search.html
- **AgentCore Policy — Bedrock Guardrails support** — Policy now supports Bedrock Guardrails, evaluating outputs of authorized agent actions and inputs to gateway targets for prompt-injection attempts, harmful content, and sensitive-data exposure. Checks run at the gateway layer, outside agent code, so every tool/context source routed through the gateway is automatically governed. Policies authored via natural language or policy-as-code. Distinct from the previously reported Cedar-based Policy. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-guardrails.html
- **Gateway — new target types** — three new/GA gateway target classes: **HTTP passthrough targets** (route to any HTTP endpoint without protocol translation — front agent URLs, external APIs, A2A agents, external MCP servers, custom inference endpoints, with unified auth/policy/observability and optional session stickiness); **Inference targets** (front model providers with model discovery, model-ID translation, path rewriting, and per-model token limits); and **AgentCore Runtime-agent targets — GA** (send gateway traffic directly to a runtime agent, with API-schema-driven guardrails and request/response interceptor Lambdas). Sources: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-http-passthrough.html , https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-inference-connector.html , https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-http-runtime.html
- **Runtime — Interactive Shells (Terminals)** — AgentCore Runtime now supports interactive shell sessions giving agents persistent terminal access to their sandboxed environment; env vars, working directories, and running processes persist across commands for the session lifetime, with up to 10 concurrent shell sessions per runtime session. Distinct from one-shot command execution (`InvokeAgentRuntimeCommand`). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-command-shell.html

## New Coverage Required

- **[AISPM] [HIGH] Amazon Bedrock AgentCore — Managed Knowledge Base (GA)**: New fully managed RAG knowledge base queryable by agents through the Gateway as a pre-built target type, with six native ingestion connectors (Amazon S3, SharePoint, Confluence, Google Drive, OneDrive, Web Crawler), automatic syncing, managed vector storage, hybrid/multimodal retrieval, and auto-generated role-based permissions. Introduces inventory entities Zenity does not yet monitor: managed knowledge bases, their six data-source connectors (each a distinct enterprise-data flow into agents), KB-as-gateway-target bindings, and the generated IAM permissions. Prime toxic-combination surface — an overbroad connector (e.g. a whole SharePoint/Drive) wired to a broadly-reachable agent is a direct data-exposure path AISPM must discover and map. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/knowledge-base.html
- **[AISPM] [HIGH] Amazon Bedrock AgentCore — Web Search Tool (GA)**: New fully managed built-in tool (AWS Summit NY, June 17, 2026) that grounds agents in live web content, exposed as a built-in MCP connector target on the AgentCore Gateway. A new tool/connector entity that gives agents outward web reach — AISPM must inventory which gateways/agents expose the Web Search target and treat it as a sensitive external-reach capability. It is also an inbound untrusted-content channel: AIDR should monitor returned snippets/source URLs as an indirect-prompt-injection and data-provenance surface. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search.html
- **[AIRT] [MEDIUM] Amazon Bedrock AgentCore — Policy + Bedrock Guardrails**: AgentCore Policy now integrates Bedrock Guardrails to evaluate agent-action outputs and gateway-target inputs for prompt injection, harmful content, and sensitive-data exposure, enforced at the gateway layer outside the agent's code (distinct from the previously reported Cedar-based Policy). This is both a governance control AISPM should map (which gateways/targets are guarded, and gaps where they are not) and a bypass target AIRT must probe — guardrail evasion at the gateway boundary, and confirming every new tool/context source is actually routed through the guarded gateway. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-guardrails.html
- **[AISPM] [MEDIUM] Amazon Bedrock AgentCore — new Gateway target types (HTTP passthrough, Inference, Runtime-agent)**: Three new gateway target/connector classes greatly expand an agent's reachable surface through a single gateway: HTTP passthrough targets front arbitrary APIs, external MCP servers, A2A agents, and custom inference endpoints; Inference targets front model providers with per-model token limits and model-ID translation; Runtime-agent targets (GA) route directly to runtime agents. Each is a new connector entity Zenity must enumerate and govern — external-MCP-server and A2A-agent passthroughs in particular are notable toxic-combination sources (an agent reaching an unvetted external MCP server or peer agent through the gateway). Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-http-passthrough.html
- **[AIRT] [MEDIUM] Amazon Bedrock AgentCore — Runtime Interactive Shells (Terminals)**: AgentCore Runtime now grants agents persistent interactive shell sessions — environment variables, working directories, and running processes persist across commands for the session lifetime, with up to 10 concurrent shells per runtime session. A new stateful command-execution surface distinct from one-shot `InvokeAgentRuntimeCommand`, broadening tool-execution and post-exploitation risk (persistent process/state, lateral movement within the sandbox). AIRT should add coverage for agent shell-session abuse and command-injection-to-shell paths; AISPM should treat interactive-shell access as a sensitive capability binding on an agent runtime. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-command-shell.html
