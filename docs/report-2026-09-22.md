## Platform Details

### Amazon Bedrock AgentCore

The September 2026 release-notes section grew from 2 entries to 4. Both new entries are in the managed **harness** (GA), which is the AgentCore agent-orchestration layer.

- **Harness: Lifecycle hooks** — hooks fire at `before_invocation`, `before_tool_call`, `after_tool_call` and `after_invocation`, including for inline-function tool calls. An AWS Lambda target returns a synchronous `allow` or `deny` that can stop an invocation or skip a tool call; Amazon SNS and Amazon EventBridge targets receive non-blocking notifications. `InvokeHarness` emits a `hookEvent` for each configured hook that fires. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-lifecycle-hooks.html
- **Harness: Custom OpenAI-compatible endpoints** — OpenAI model configurations now accept an optional `apiBase` field, routing direct OpenAI requests through a customer-specified gateway, proxy, self-hosted endpoint or regional endpoint. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-models.html

### Claude Enterprise (Anthropic)

- **Life Sciences Verification Program (September 17, 2026)** — a vetting-gated entitlement that replaces an organisation's biology-related safety classifiers with a more permissive set. Two tiers: *Standard Use* (Mythos, Opus and Sonnet with classifiers tuned permissive for science tasks) and *High-risk Use*, an add-on that **removes all safeguards blocking life-sciences requests** for a named project. Cyber classifiers and other safeguards are retained. Grants are annual (Standard) or bi-annual (High-risk), scoped to declared use cases, and enforcement shifts from real-time blocking to offline pattern analysis. Source: https://www.anthropic.com/news/life-sciences-verification-program

### Google Gemini Enterprise

- **Transfer agent ownership (September 21, 2026)** — administrators holding `roles/discoveryengine.agentspaceAdmin` or `roles/discoveryengine.admin` can reassign ownership of a shared agent to another user, including themselves. Shared agents only; the new owner becomes sole owner and the previous owner is downgraded to `agentUser`. Targets may be Google accounts or Workforce Identity Federation principals. Any schedule or event trigger on the agent is marked disabled by the transfer and must be re-enabled by the new owner. Source: https://docs.cloud.google.com/gemini/enterprise/docs/share-custom-agents

## New Coverage Required

- **[AIDR] [HIGH] AgentCore harness lifecycle hooks**: A new synchronous interception and control surface inside the AgentCore agent loop. Four hook points (`before_invocation`, `before_tool_call`, `after_tool_call`, `after_invocation`) can each bind a Lambda that returns `allow`/`deny` and can halt an invocation or suppress a tool call, plus SNS/EventBridge fan-out targets. This introduces new inventory entities (harness hook configurations, their Lambda/SNS/EventBridge targets) and a new activity type — the `hookEvent` records emitted by `InvokeHarness` — which is a first-class detection feed for what an AgentCore agent actually invoked. It is also a control plane an attacker with harness-config write access can neuter or repurpose: replacing a `deny` Lambda silently removes the customer's own tool-call gating, and a `before_tool_call` Lambda sees every tool argument, making it an exfiltration point. Zenity must inventory hook configurations, alert on hooks removed or repointed, and ingest `hookEvent` as an AIDR activity source. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-lifecycle-hooks.html

- **[AIRT] [HIGH] Anthropic Life Sciences Verification Program — entitlement-based safeguard removal**: A verified organisation's Claude deployment can run with biology safety classifiers relaxed (Standard Use) or, at the High-risk tier, with all life-sciences-blocking safeguards removed for a named project. Guardrail behaviour is therefore a property of the *entitlement attached to the workspace/API key*, not of the model — the same `claude-mythos-5`/Opus/Sonnet model ID behaves differently for an entitled org, and Anthropic explicitly moves that tier from real-time blocking to offline pattern analysis. Red-team probes that infer safety posture from refusals will pass falsely against an entitled deployment. AIRT needs a bio-domain probe set, and AISPM needs to record the LSVP entitlement and tier as a property of the Anthropic connection so an unexpected High-risk grant is a finding. Directly parallels the Mythos-5 safeguard-lifting pattern already tracked. Source: https://www.anthropic.com/news/life-sciences-verification-program

- **[AISPM] [MEDIUM] AgentCore harness custom OpenAI endpoint (`apiBase`)**: OpenAI model configs in the AgentCore harness now take an `apiBase` pointing at any OpenAI-compatible gateway, proxy, self-hosted or regional endpoint. This is a new outbound model-traffic path that leaves AWS-observed inference entirely — every prompt, tool result and completion for that agent can be routed to an arbitrary third-party host set by a single config field, with no code change and no new IAM resource. AISPM must surface `apiBase` per harness configuration, treat a non-default value as an unmonitored data-egress edge, and flag agents whose model traffic bypasses Bedrock. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-models.html

- **[AISPM] [MEDIUM] Gemini Enterprise agent ownership transfer**: A new administrative action that reassigns the sole owner of a shared agent, demoting the previous owner to `agentUser`, and that accepts Workforce Identity Federation principals as well as Google accounts. This mutates an inventory relationship Zenity already models (agent → owner) through a path that is not agent creation, so ownership drift will go unobserved unless the transfer is tracked; it is also a plausible privilege-consolidation move — an admin can make themselves the owner of any shared agent in the tenant. The transfer additionally disables the agent's schedule and event triggers, silently changing autonomous-execution posture. AISPM should treat owner change on an existing agent, and trigger-state change caused by it, as distinct monitored events. Source: https://docs.cloud.google.com/gemini/enterprise/docs/share-custom-agents
