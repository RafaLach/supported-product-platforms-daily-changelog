## Executive Summary

**This scan covers a 7-day gap** — the previous run was 2026-08-14 — and it is the largest live-movement window this monitor has seen. Eight platforms moved on their own dated release streams, including two that had been static for months. Twenty-four findings.

The four most consequential:

- **Anthropic shipped a browser-driving toolset and took Skills GA on the API (Aug 19).** The new **browser use tool** (`browser_toolset_20260801`) is a client toolset that reads a page's **accessibility tree** and acts on **element references** rather than pixels, with tab management, form input, file upload, and — behind opt-in flags — **`javascript_exec`, `read_console` and `read_network`**. Anthropic's own documentation leads with the prompt-injection risk and tells implementers to treat all page content as untrusted. Alongside it, **Agent Skills and the Skills API (`/v1/skills`) went GA**, making a skill a first-class, enumerable API resource rather than a beta-gated one.

- **Microsoft Copilot Studio's changelog finally moved — and the July entries are governance-relevant.** After sitting on "June 2026" across four consecutive scans, a **July 2026** section appeared. Two items matter most: agents on the GitHub Copilot harness can now take an **MCP server or a workflow as a tool**, and **Copilot Studio now creates a Microsoft Entra Agent ID for every new agent with the environment-level opt-out removed** — so every new agent is now an addressable directory principal, whether the maker wanted one or not.

- **AWS reversed course on its Bedrock endpoints, and the reversal changes detection.** Last week's headline was that AWS recommended `bedrock-mantle` over `bedrock-runtime`. On **Aug 15 and Aug 19** AWS **reversed that guidance** and, more importantly, moved the OpenAI- and Anthropic-compatible routes onto `bedrock-runtime` itself: `bedrock-runtime.{region}.amazonaws.com/anthropic` and `/openai/v1`. Both endpoints now serve foreign API shapes, so an endpoint-based split no longer tells you which wire format to expect. The same work surfaced **Bedrock Projects and Workspaces** — a control-plane isolation entity, managed by a Projects API, that this monitor has never inventoried.

- **AgentCore agents can now negotiate and settle open-ended payments.** AgentCore payments added the **x402 `upto` scheme** (pay a metered amount up to a ceiling, settled through the Permit2 contract) and the **Machine Payments Protocol**, in which a merchant returns a `WWW-Authenticate: Payment` challenge and AgentCore parses it, checks the session budget, **signs with the wallet**, and returns a spendable credential across `evm`, `tempo` and `solana`. **Coinbase quick create** now provisions the underlying CDP credentials through a browser authorization, so no human ever handles the key.

**Also new**: OpenAI connected **Codex to GitLab** (beta) with `@codex` triggers on issues and merge requests and automatic reviews, and shipped an **Apple Messages plugin** that requires **Full Disk Access** and can read and send iMessage, SMS and RCS. Google took **A2UI + A2A agent registration GA** with v0.9 support. **Cursor became a code host** — Origin is a git forge with bidirectional GitHub sync.

### Claude Enterprise (Anthropic) — two new dated entries, Aug 18 and Aug 19

Read from `https://platform.claude.com/docs/en/release-notes/api`; the two Anthropic URLs in `sources.json` still return 404.

- **Browser use tool (`browser_toolset_20260801`), Aug 19.** A client toolset for driving a browser the *application* hosts, working inside a viewport rather than a whole desktop. Reads the page's **accessibility tree** via `read_page`, returning stable element references (`[ref_1]`…) that Claude acts on by reference instead of coordinates; `find` locates elements from natural-language descriptions and `get_page_text` extracts visible text. Members include `navigate` (with `back`/`forward`/`reload`), the full pointer and keyboard set, `form_input`, `screenshot`, `zoom`, and tab management (`new_tab`, `list_tabs`, `switch_tab`, `close_tab`). The application must report tab inventory through `browser_state` blocks and downloads through `state_changes`. Anthropic's guidance: run the browser in a dedicated container with no credentials, enforce domain allowlisting at the network layer, refuse `javascript:`/`file:`/`data:`/`chrome:` schemes, sanitize page-supplied URLs and titles, and require human confirmation for consequential actions. Source: https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool

Source: https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes#use-memory-stores

### Amazon Bedrock AgentCore — five new August entries

Read from `https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html`; `sources.json` still points at `doc-history.html`, which renders title/nav only.

- **Payments: x402 `upto` scheme and Machine Payments Protocol (MPP).** The `upto` scheme **pays a metered amount up to a ceiling and settles through the Permit2 contract**, in addition to the existing `exact` scheme. MPP is an HTTP-native standard using the standard authentication-challenge flow: a merchant returns `WWW-Authenticate: Payment` in a `402 Payment Required`, the agent forwards the challenge verbatim to `ProcessPayment` with `paymentType=MPP`, and **AgentCore parses the challenge, checks the session budget, signs with the wallet, and returns a ready-to-send credential** that the caller replays in an `Authorization` header. Supports `evm`, `tempo` and `solana` payment methods, with provider support varying by connector type. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-process-payment.html
- **Payments: Quick create for Coinbase payment connectors.** AgentCore payments **provisions your Coinbase CDP credentials for you** — you authorize through Coinbase in a browser and the service creates the payment credential provider on your behalf. No API keys are generated or pasted by a human. Coinbase only; Stripe (Privy) still uses supplied credentials. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-create-manager.html
- **Evaluations: Skill evaluators.** Two built-in tool-level evaluators — `Builtin.SkillSelectionAccuracy` (did the loaded skill fit the task, given the catalog) and `Builtin.SkillInstructionFollowing` (a five-point rating of how fully the agent followed the skill's prescribed steps). One result per skill invocation, anchored to the tool-call span that loaded the skill. Custom `TOOL_CALL` evaluators can read the same signals through the `invoked_skill`, `skill_content`, `available_skills` and `user_message` placeholders. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/skill-evaluators.html
- **Evaluations: Third-party evaluators.** Evaluators from the **DeepEval and AutoEval** open-source libraries, either managed (selected by ID and run by AWS on a model it operates) or derived (the library's logic run on the customer's own model and inference). Both are discoverable through `ListEvaluators` alongside built-in and custom evaluators. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/third-party-evaluators.html
- *(Not reported: Coinbase wallet usage billed through AWS Marketplace — billing plumbing; memory/policy/harness in GovCloud (US-West) — region expansion.)*

## New Coverage Required

- **[AIRT] [HIGH] Anthropic shipped a browser-driving toolset that reads the accessibility tree and can be flagged into JavaScript execution, console and network capture**: `browser_toolset_20260801` is a new client toolset that drives a browser the customer's own application hosts, working inside a viewport rather than a whole desktop. Its reading model is the finding's core: `read_page` returns the page's **accessibility tree** as text with stable element references (`[ref_1]`, `[ref_2]`…) and Claude then acts **by reference** rather than by coordinate, with `find` resolving elements from natural-language descriptions and `get_page_text` extracting visible text. That makes the agent's interaction with a page semantic and reliable in a way screenshot-and-click never was, which raises the ceiling on what a prompt injection embedded in a page can actually accomplish. **Anthropic's own documentation leads with that risk** — it instructs implementers to treat every page-supplied string (titles, URLs, text) as untrusted, sanitize before returning it to Claude, refuse `javascript:`/`file:`/`data:`/`chrome:` schemes in the navigate handler, enforce domain allowlisting **at the network layer**, run the browser in a dedicated container with no credentials, and require human confirmation for purchases, account modifications and messaging. Four members are optional and off by default, and each one is a distinct escalation an implementer can silently enable: **`javascript_exec`** runs arbitrary JavaScript in page context, **`read_console`** and **`read_network`** expose logs and requests that routinely carry tokens and secrets (Anthropic explicitly says to redact before enabling them), and **`file_upload`** sets files on `<input type="file">` from either executor filesystem `paths` or application-staged `document_ids` — with the warning that a malicious page could otherwise direct uploads of any accessible file. AIRT should build page-hosted injection tests against reference-based interaction specifically, and test whether a hostile page can induce navigation to a non-HTTP scheme, an unapproved consequential action, or a `file_upload` outside its intended directory. AISPM should discover which applications enable this toolset and, per deployment, which optional members are turned on, treating `javascript_exec` and `file_upload` as privileged configuration; AIDR should ingest `browser_state` tab inventories and `state_changes` download events as agent activity, since a download reported there is data leaving a page and landing on the executor. Source: https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool

- **[ENDPOINT] [HIGH] The ChatGPT Mac app can now read and send iMessage, SMS and RCS, and requires Full Disk Access to do it**: OpenAI shipped an **Apple Messages plugin** that lets ChatGPT search a user's entire Messages history, summarize past conversations, draft replies, and **send messages** through Messages. It covers **iMessage, SMS and RCS**, so it reaches SMS-delivered content including one-time passcodes and MFA codes. The permission requirement is the finding: the integration needs **Full Disk Access** in macOS System Settings, plus access to contact names and automation tooling — a grant that extends far beyond Messages and that endpoint policy at most enterprises treats as high-privilege. Two more properties matter for coverage. First, the **send-approval model degrades by design**: sends require user approval by default, but users can choose **"Always allow sending to this chat"**, which OpenAI itself warns removes the final review before ChatGPT sends on the user's behalf — so a per-conversation toggle silently converts a human-in-the-loop control into autonomous outbound messaging. Second, availability is **narrower than "the ChatGPT desktop app"**: the plugin ships only in the **Apple Silicon (arm64)** build and does nothing on Intel Macs, the web, mobile, Codex CLI or the IDE extension — reinforcing that per-OS-and-architecture feature modelling is now required rather than optional. It is available on all plans and installed from Plugins > Public, and works from **both ChatGPT Work and Codex**, so it is reachable from a coding agent as well as the chat client. ENDPOINT should detect the plugin's installed and enabled state per device, detect the Full Disk Access grant to the ChatGPT app as a distinct high-risk condition, and inventory which conversations have persistent send approval; AIDR should treat agent-originated messages as an outbound data-flow channel; AIRT should test whether content arriving in a message thread can steer the agent into sending on the user's behalf where persistent approval is already granted. Source: https://learn.chatgpt.com/docs/changelog

- **[AISPM] [HIGH] Codex now connects to GitLab with `@codex` triggers on issues and merge requests and automatic reviews**: OpenAI extended Codex cloud beyond GitHub. You can now **connect GitLab projects**, create cloud environments against them, **trigger tasks by mentioning `@codex` on issues and merge requests**, and **enable automatic reviews**. This is a new code-host integration surface, not a variation on an existing one, and it matters for three reasons. It is a **second source-control identity to discover and scope**: setup covers webhook permissions, so Codex holds a standing credential and webhook grant against GitLab projects, and the effective blast radius is whatever that credential can read and write across connected projects. It **moves the trigger boundary out of the developer's hands**: with `@codex` mentions and automatic reviews enabled, an agent task can be started by anyone who can comment on an issue or open a merge request — including, on projects that accept outside contributions, someone who is not an employee. And it **extends the injection path**: issue and merge-request bodies are attacker-influenceable text that now reaches an agent with repository access, the same pattern Zenity should already be testing on the GitHub side. Note also that self-hosted GitLab remains reachable through the GitLab MCP server as a separate path, so a customer may have both a first-party Codex-GitLab connection and an MCP-mediated one. AISPM should discover Codex-to-GitLab connections, resolve the authenticating identity and its project scopes, enumerate which projects have automatic reviews enabled, and flag connections on projects that accept external contributions; AIRT should test `@codex` mention-triggered injection from issue and merge-request content. Source: https://learn.chatgpt.com/docs/cloud

- **[AISPM] [HIGH] Copilot Studio agents can now take an MCP server or a workflow as a tool on the GitHub Copilot harness**: The July 2026 Copilot Studio release adds the ability to attach a **workflow** or an **MCP server** as a tool to agents built on the **GitHub Copilot harness** — the new orchestration runtime that went production-ready preview in June. Both are new tool types on a new harness, which means the tool-attachment surface Zenity inventories for Copilot Studio is no longer complete. The MCP case is the more consequential: an MCP server attached as a tool brings an external, independently-operated endpoint into the agent's capability set, with its own tool list, its own authentication, and its own change cadence that no Copilot Studio review gate observes after attachment. The workflow case is a **privilege-composition** problem — a workflow is a multistep automated process that may itself hold connections and credentials, so attaching one grants the agent the workflow's reach rather than just a single action, and the agent's effective permissions become the union of its own and every attached workflow's.
