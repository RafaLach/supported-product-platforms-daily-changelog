## Platform Details

### Cursor

- **Shared Canvases (Version 3.5, May 20, 2026)**: New external sharing surface for agent-produced interactive artifacts. Teams share dashboards and reports created by Cursor agents via browser links with read-only access — agent output now reaches users outside the IDE/Cursor account boundary for the first time. Source: https://cursor.com/docs/agent/tools/canvas
- **Cursor Automations integration into Agents Window + multi-repo / standalone configurations (May 20, 2026)**: Automations now live inside the Agents Window. Supports multi-repository configurations and standalone setups (no repository required). Five new templates ship out of the box: Slack digest, analytics, FAQ, finance, customer health monitoring. Source: https://cursor.com/docs/cloud-agent/automations

## New Coverage Required

- **[AISPM] [MEDIUM] Cursor — Shared Canvases (v3.5)**: Cursor agents can now produce interactive artifacts (dashboards, reports) that are externally shareable via browser links with read-only access. This creates a new outbound data-flow surface — agent output crosses the Cursor tenant boundary to non-Cursor recipients. Introduces new inventory entities: shared-canvas artifacts, share-link tokens, and external-reader identities. AISPM must discover Shared Canvas instances per workspace, map which agents are authorized to publish externally, and flag toxic combinations such as a canvas containing source-derived data being shared to an unauthenticated browser link. Source: https://cursor.com/docs/agent/tools/canvas
- **[AISPM] [MEDIUM] Cursor — Automations multi-repo / standalone & expanded template surface**: Cursor Automations are now first-class Agents Window citizens, can operate across multiple repositories in one automation, and can run standalone (no repo at all). Five new templates (Slack digest, analytics, FAQ, finance, customer health monitoring) expand the kinds of business workflows automations execute. AISPM should treat each Automation as an inventory entity with a defined repo-set scope, recognize standalone automations as a distinct class (no repo-bounded blast radius), and add the new template types to the catalog so any standardized template instance can be discovered and audited. Source: https://cursor.com/docs/cloud-agent/automations
