## Platform Details

### Microsoft Copilot Studio — May 2026 notable-changes wave (new vs. cached April 2026 baseline)

- **Agent inventory schema** — Discover and audit all Copilot Studio agents in the tenant from the admin center, the Power Platform API, or **Azure Resource Graph**. Per-agent metadata includes creator, last-published time, deployed channels, authentication method, and capabilities; covers draft and published agents (excludes V1/Classic bots), refreshed roughly every 20 minutes. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-agent-inventory
- **Computer use is now generally available** + new **computer use standalone tools (preview)** — Computer Use (CUA-powered web/desktop UI automation on Windows) moved from preview to GA; standalone computer-use tools add modular, reusable UI-automation tools with built-in governance, model selection, and observability. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use
- **New agent-flow / workflow nodes** — **Microsoft 365 Copilot node** sends prompts to Microsoft 365 Copilot or a specific agent from within a workflow (research/audit-drafting automation); **Prompt node** makes a single AI call with dynamic content and per-node model selection. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/microsoft-365-copilot-node-workflow
- Also in the May wave (noted, not raised as findings): consent-based recording for voice agents, asynchronous (long-running) agent-flow responses, a consolidated agent readiness/issue-status page (preview), and **Mistral Medium 3.5** as an experimental primary model. Microsoft Entra agent identities (preview) also appears but was already cached as a Nov 2025 item. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new

### ChatGPT Enterprise (OpenAI) — Codex CLI 0.137.0 (June 4, 2026)

- **Hosted web and image tools in code-mode flows** with parallel web search; **Multi-agent v2** with runtime-choice persistence per thread; **remote-control clients can manage pairing and controller grants via app-server RPCs**; enterprise/admin flows now surface monthly credit limits and **cloud-managed config bundles**; plugin workflows gained machine-readable JSON output and cached remote catalog suggestions. (Codex app 26.602, same day, added activity insights/share cards and Computer Use startup-readiness hardening.) Source: https://developers.openai.com/codex/changelog

### Cursor — 3.7 + Enterprise Organizations (June 3–4, 2026) [watching tier]

- **Enterprise Organizations (GA)** — a new top-level **Organization** container above Teams, plus **Groups** (lightweight user cohorts that cut across/within teams). Each carries its own security, governance, budget, **model access**, spend limits, and **agent permissions**; org-level identity management and a spend/token rollup across teams; users move between teams via dashboard/API/CSV ("most permissive setting wins" on overlap). Source: https://cursor.com/changelog/enterprise-organizations
- **3.7 (June 4)** Canvas Design Mode (annotate UI elements in canvases), interactive context-usage report, full-screen canvas sharing, and agent-embedded buttons that trigger specific prompts. Source: https://cursor.com/changelog

## New Coverage Required

- **[AISPM] [HIGH] Microsoft Copilot Studio Agent inventory schema**: A new tenant-wide agent inventory lets admins discover and audit every Copilot Studio / Agent Builder agent via the Power Platform admin center, the Power Platform API, and **Azure Resource Graph**, exposing per-agent metadata (creator, last-published time, deployed channels, authentication method, capabilities) for both draft and published agents. This is a first-class inventory/discovery surface that AISPM should ingest directly — it is effectively the platform's own agent inventory feed and the authoritative source for mapping Copilot Studio agents as entities, their owners, channels, and auth posture, and for flagging toxic combinations (e.g., unauthenticated/anonymous-channel agents, orphaned-owner agents, or agents with broad capabilities). AISPM must consume this schema to keep Copilot Studio agent coverage complete. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-agent-inventory
- **[AISPM] [MEDIUM] Copilot Studio Computer Use GA + standalone computer-use tools**: Computer Use (CUA-powered automation that controls browsers and Windows desktop apps on a user's behalf) moved to general availability, and a new **standalone computer-use tool** type adds modular, reusable UI-automation tools with their own governance, model selection, and observability. This expands an existing capability into a discrete, reusable inventory entity: AISPM should map standalone computer-use tools (and the agents/flows that attach them) and treat a Computer-Use-enabled agent — which can click, type, and read any on-screen content with built-in credentials — as a high-privilege, GUI-level execution path subject to AIRT testing for prompt-injection-driven unintended actions. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use
- **[AISPM] [MEDIUM] Copilot Studio Microsoft 365 Copilot node + Prompt node (new agent-flow building blocks)**: Two new workflow/agent-flow nodes shipped in May. The **Microsoft 365 Copilot node** lets a workflow send prompts to Microsoft 365 Copilot (or a specific agent) and consume the result — a new agent-to-Copilot data flow that can pull tenant grounding data into automated processes. The **Prompt node** makes a single inline AI call with dynamic content and per-node model selection. AISPM should add these node types to its Copilot Studio flow inventory and map the M365 Copilot node as a new data-flow edge (workflow → M365 Copilot → grounded enterprise data), which AIDR should also treat as a new activity/data-flow surface. Source: https://learn.microsoft.com/en-us/microsoft-copilot-studio/microsoft-365-copilot-node-workflow
- **[ENDPOINT] [MEDIUM] OpenAI Codex CLI 0.137.0 — hosted web/image tools in code-mode, Multi-agent v2, remote-control grant management**: The June 4 Codex CLI release lets code-mode flows use hosted web and image tools with parallel web search (new autonomous web-egress/tool surface from inside code execution), adds Multi-agent v2 with per-thread runtime-choice persistence (expanded local multi-agent orchestration), and lets remote-control clients manage pairing and controller grants via app-server RPCs (a remote-control authorization surface), plus cloud-managed config bundles for enterprise/admin. ENDPOINT should track Codex CLI installs that can now reach the web and spawn persistent multi-agent runs locally, and treat remote-control pairing/controller grants as a new device-access surface on monitored machines. Source: https://developers.openai.com/codex/changelog
- **[AISPM] [MEDIUM] Cursor Enterprise Organizations (new org/group governance & identity entities)**: Cursor (watching tier) added a generally-available **Organization** layer above Teams plus cross-cutting **Groups**, each with its own security, governance, budget, **model access**, spend limits, and **agent permissions**, org-level identity management, and a spend/token rollup. These introduce new governance/identity entities for a monitored endpoint AI tool: AISPM should map Cursor organizations, teams, and groups — and especially per-group model access and agent permissions — since "most permissive setting wins" on overlapping membership can silently grant a user broader model/agent capability than their primary team allows (a privilege-aggregation toxic combination). Source: https://cursor.com/changelog/enterprise-organizations
