## Investigated and dismissed

**Amazon Bedrock AgentCore data-plane API — apparent 25-operation delta. Not a real change.**

This scan's fetch of the AgentCore Actions reference returned Payments (`CreatePaymentInstrument`, `ProcessPayment`, `GetPaymentInstrumentBalance`, payment sessions), A/B Testing (`*ABTest`), Batch Evaluations (`*BatchEvaluation`), Recommendations (`*Recommendation`), `InvokeHarness`, `InvokeBrowser`, `SearchRegistryRecords` and `DeleteCapacityProviderSession` as operations absent from `cache/aws_agentcore_api.txt`.

All of them were already reported:

- Payments, A/B Testing, Batch Evaluations, Recommendations, `InvokeHarness`, `InvokeBrowser` — reported 2026-05-18 and 2026-05-21; the x402 `upto` scheme and Machine Payments Protocol extensions reported 2026-08-21.
- `SearchRegistryRecords` — reported 2026-04-10 and 2026-05-21.
- `DeleteCapacityProviderSession` — reported 2026-08-07 with the Runtime Instances / capacity-provider finding.

The authoritative 2026-08-07 capture recorded **71 operations**, verified operation-for-operation unchanged on 2026-08-24 and 2026-08-26. Today's fetch names 66 operations, every one of which falls inside that previously-reported set — nothing appeared today that has not already been reported. (The 66-vs-71 gap is a shortfall in today's page rendering on our side, not a removal; removals are out of scope either way.)

**Root cause:** `cache/aws_agentcore_api.txt` (2.8 KB) was a *prose summary* of the operations page rather than the operation list itself, so it silently omitted whole families and manufactured a false delta on every structural diff. Fixed this scan — both AgentCore API cache files now hold the literal operation list, with a header warning against re-summarising. The general lesson for this monitor: **cache literal lists for enumerable API surfaces; never cache a summary of one.**
