## Platform Details

### Amazon Q Developer
- **Amazon Q artifacts (preview) — May 21, 2026**: New Q Developer capability that delivers responses enriched with table and chart visualizations *and* executes cross-service jobs in the AWS Management Console. Example: "Connect EC2 instance to an S3 bucket" returns a Q artifact that **grants permissions on the EC2 instance profile** and **makes bucket policy changes**. Supported services include EC2, RDS, Lambda, S3. All visualization data is persisted in **us-east-1** regardless of the source region. AmazonQFullAccess and AmazonQDeveloperAccess managed policies updated with `q:CreateArtifact`, `q:GetArtifact`, `q:GetArtifactActionResult`, `q:PerformArtifactAction`. Source: https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/chat-artifacts.html

### OpenAI Codex
- **Codex 26.519 — Appshots (macOS), May 21, 2026**: New macOS-only capture mechanism — pressing both Command keys sends the frontmost application window to Codex with a screenshot. The capture pulls **text the app exposes including content outside the visible scroll area** into the thread as an attachment. Source: https://developers.openai.com/codex/changelog
- **Codex 26.519 — Goal Mode GA, May 21, 2026**: Goal Mode promoted from experimental to GA. Codex now accepts a multi-hour objective and runs it autonomously **across session breaks, token-budget resets, and interruptions**. Live in the Codex app, VS Code and JetBrains extensions, and CLI 0.128.0+. Source: https://developers.openai.com/codex/changelog
- **Codex 26.519 — Remote Computer Use, May 21, 2026**: New capability lets Codex drive desktop applications after the device is locked, via Codex Mobile from a smartphone. Safety controls include time-bound authorization, covered-screen behavior, automatic relock on first local input, and manual unlock fallback. Source: https://developers.openai.com/codex/changelog
- **Codex Plugin Sharing — May 21, 2026**: ChatGPT Business teams can distribute **reusable plugin bundles** through marketplace sources. Discovery is "marketplace-aware" with remote collection support. Source: https://developers.openai.com/codex/changelog
- **Codex CLI 0.133.0 — May 21, 2026**: Permission profiles expanded with **list APIs, inheritance support, and Windows sandbox integration**. `codex remote-control` operates as a foreground command. Extensions expose new lifecycle events including subagent transitions and tool execution. Source: https://developers.openai.com/codex/changelog

### Amazon Bedrock AgentCore
- **AgentCore Runtime — bring-your-own file system, May 6, 2026**: New AgentCore Runtime capability that lets developers attach **Amazon S3 Files** and **Amazon EFS access points** directly to agent runtimes. The file system is **mounted into every session at a developer-specified path**, and agents read/write using standard POSIX-style file operations — "no custom mount code, no privileged containers, no download orchestration before the agent can start working." Sub-millisecond latency for active data, NFS close-to-open consistency. Multiple sessions/agents can share the same file system simultaneously, persisting intermediate results across sessions. Requires VPC configuration + access point ARN. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-filesystem-configurations.html

### Anthropic — Project Glasswing
- **Project Glasswing: Initial update — May 22, 2026**: Anthropic published its first results update for Project Glasswing (the cybersecurity initiative powered by Claude Mythos Preview, originally introduced April 7, 2026). Mythos Preview has now uncovered **10,000+ high/critical-severity vulnerabilities** across widely used software systems via a coalition of ~50 trusted partners. **Cloudflare** (~2,000 bugs, 400 H/C-severity — fewer false positives than human testers), **Mozilla** (271 vulnerabilities fixed in Firefox 150, 10× more than older Claude models), and **Verizon** (joined May 2026) are confirmed partners. Open-source program scanned 1,000+ projects, found 6,202 H/C-severity vulnerabilities (90.6% confirmed legitimate true positives, 62.4% validated as H/C-severity). Expansion plan includes **U.S. and allied governments**. Anthropic states: "no company — including itself — has yet developed safeguards reliable enough to prevent the malicious use of models with Mythos-level capabilities." Source: https://www.anthropic.com/research/glasswing-initial-update

## New Coverage Required

- **[AISPM] [HIGH] Amazon Q Developer artifacts (preview) — Q can perform cross-service AWS actions**: Brand-new capability that promotes Amazon Q from a chat surface to an **action-executing agent in the AWS Management Console**. Introduces three new inventory entities: **Q artifact** (the response payload), **Q artifact action** (the cross-service job, e.g., grant S3 bucket policy + modify EC2 instance profile), and **Q artifact action result**. New IAM actions `q:CreateArtifact`, `q:GetArtifact`, `q:GetArtifactActionResult`, `q:PerformArtifactAction` are now baked into the **AmazonQFullAccess** and **AmazonQDeveloperAccess** managed policies, so every principal granted these policies inherits artifact-action capability transitively. AISPM must inventory which IAM principals carry these permissions, treat Q artifacts as a new high-privilege agent-tool primitive (cross-service mutations on EC2/RDS/Lambda/S3 from a chat prompt), and surface us-east-1 visualization data as a new data-residency signal. New toxic combination: overprivileged IAM principal + Q artifact action permissions + sensitive workload (production, regulated). Source: https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/chat-artifacts.html
- **[AIRT] [HIGH] Amazon Q Developer artifacts — prompt-injection-driven AWS resource mutation**: New attack surface. A prompt-injection that reaches Amazon Q in the AWS console can trigger `q:PerformArtifactAction` to mutate live infrastructure (e.g., bucket policies, instance-profile permissions). AIRT should add automated tests for prompt-injection-to-artifact-action chains, artifact action authorization bypasses, and unexpected cross-service writes initiated through Q. Source: https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/chat-artifacts.html
- **[ENDPOINT] [HIGH] OpenAI Codex — Appshots (macOS screen + non-visible text exfiltration vector)**: Codex now ingests the frontmost macOS window's screenshot **plus any text the app exposes, including content outside the visible scroll area**, via a double-Command-key shortcut. This is a new endpoint data-egress channel — a Codex agent prompt can now reference contents of any window the user surfaces (Slack threads, password managers, email drafts, CRM records). ENDPOINT must add Appshots as a Codex local data primitive, recognize Mac-windowed apps as a per-window inventory class, and flag double-Command captures in sensitive apps. Source: https://developers.openai.com/codex/changelog
- **[ENDPOINT] [HIGH] OpenAI Codex — Goal Mode GA (multi-hour autonomous objective execution)**: Goal Mode promoted to GA. Codex now runs **multi-hour autonomous objectives** that persist across session breaks, token-budget resets, and interruptions, live in the app, VS Code, JetBrains, and CLI. ENDPOINT must treat each Goal as a distinct durable session resource (not a one-shot prompt), inventory active Goals per user, and track which IDE extension and CLI version is hosting each Goal. New telemetry class: Goal lifecycle events (start, pause, resume, complete) and the persistent objective text. Source: https://developers.openai.com/codex/changelog
- **[ENDPOINT] [HIGH] OpenAI Codex — Remote Computer Use (locked-Mac control from Codex Mobile)**: First time Codex agency persists past the screen lock. From a smartphone via Codex Mobile, Codex can drive desktop apps **even when the Mac is locked and screen off**. ENDPOINT must add Remote Computer Use sessions as a new endpoint class with mobile-initiated authorization, treat the time-bound authorization window as a discrete inventory event, and capture every Remote Computer Use session boundary (relock, manual unlock, screen cover). This breaks the assumption "if the device is locked, the agent is idle." Source: https://developers.openai.com/codex/changelog
- **[ENDPOINT] [MEDIUM] OpenAI Codex Plugin Sharing — marketplace plugin bundles for ChatGPT Business**: New distribution channel — ChatGPT Business teams can publish and share **plugin bundles** discoverable through marketplace sources. Plugin discovery is now "marketplace-aware with remote collection support." ENDPOINT/AISPM must inventory plugins by source (first-party vs. marketplace bundle), track which teams have published vs. installed which bundles, and treat the plugin-bundle ID as a new resource type that propagates between users. New supply-chain inventory entity. Source: https://developers.openai.com/codex/changelog
- **[ENDPOINT] [MEDIUM] OpenAI Codex CLI 0.133.0 — Windows sandbox integration + permission profile inheritance**: Codex CLI 0.133.0 adds **Windows sandbox integration** (previously macOS/Linux only) and **permission profile inheritance** with list APIs. ENDPOINT must extend the Codex CLI inventory to Windows hosts, treat Windows sandbox-bounded Codex sessions as a new class, and reconcile inherited permission profiles into the effective-permissions graph (a child profile may relax constraints set by its parent). - **[AISPM] [HIGH] AgentCore Runtime — bring-your-own file system (S3 / EFS mounted into agent sessions)**: New AgentCore Runtime capability that mounts **Amazon S3 Files and Amazon EFS access points directly into every agent session at a developer-specified path**. Each agent now has POSIX-style read/write access to potentially large enterprise data stores without custom mount code or privileged containers. Multiple sessions/agents can share the same file system simultaneously. AIDR must add a file-system-IO activity stream per AgentCore session, with read/write attribution and access-point-scoped data-flow accounting (e.g., "agent X wrote 4 GB to EFS access point Y during session Z").
