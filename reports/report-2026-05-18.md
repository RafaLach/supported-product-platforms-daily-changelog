## New Coverage Required

- **[AISPM] [HIGH] Amazon Bedrock AgentCore — Payments service (x402 protocol)**: AgentCore Payments is a brand-new service that allows agents to hold wallets and execute microtransactions through Coinbase CDP or Stripe (Privy), with configurable spending limits via `PaymentManager` and `PaymentConnector` resources. Introduces several new inventory entities (payment managers, payment connectors, payment instruments, payment sessions, agent wallet bindings, spending policies) and entirely new toxic combinations: an over-privileged agent with a funded payment instrument, weak spending limits, prompt-injection-driven payments, and a payment session bound to a tool that an attacker can drive. AISPM must discover payment instruments and their agent bindings, map spending limits, and flag combinations where untrusted-input pathways can reach `ProcessPayment` or `CreatePaymentSession`. AIDR must monitor payment-session activity as a high-signal data flow. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments.html
- **[AIRT] [HIGH] AgentCore Payments — financial-action attack surface**: For the first time, prompt injection or guardrail bypass can translate to direct monetary loss inside an AWS-managed agent runtime. AIRT must add test coverage for prompt-injection-to-payment paths, spending-limit bypass, wallet-provider abuse (CDP/Stripe), x402 v1/v2 protocol-handling flaws, and `ProcessPayment` invocation through indirect-prompt channels. Source: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-how-it-works.html
- **[AISPM] [MEDIUM] AgentCore A/B Testing, Batch Evaluations, Recommendations API suites (AgentCore Optimization)**: Three new API surfaces (`*ABTest`, `*BatchEvaluation`, `*Recommendation`) extend the AgentCore control plane under the new "AgentCore Optimization" umbrella.
