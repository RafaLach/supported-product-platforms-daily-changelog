## Platform Details

### ChatGPT Enterprise (OpenAI) — Codex

- **Codex 26.527 (May 29, 2026) — Computer Use on Windows**: The Codex app can now operate graphical desktop applications on Windows by seeing, clicking, and typing in the foreground (install the Computer Use plugin, then invoke with `@Computer` or `@AppName`). Remote control from the ChatGPT app on iOS/Android is extended to Windows devices, so a user can steer or send follow-up instructions to a Windows machine running Codex from their phone. Also added: a profile section surfacing usage stats and token activity, and thread-coordination improvements for local projects and worktrees. Source: https://developers.openai.com/codex/windows

### Cursor

- **Cursor 3.6 (May 29, 2026) — Auto-review Run Mode**: A new agent run mode (Settings → Agents → Run Mode) that allows the agent to work longer with fewer approval prompts. It applies to **Shell, MCP, and Fetch** tool calls: allowlisted calls run immediately, sandboxable calls execute in an isolated sandbox, and all other actions are routed to a **classifier subagent** that decides whether to allow the call, try a different approach, or ask the user for approval. The classifier can be steered with custom instructions. Source: https://cursor.com/changelog/auto-review

## New Coverage Required

- **[ENDPOINT] [MEDIUM] OpenAI Codex — Computer Use on Windows + mobile remote control**: Codex 26.527 extends agentic computer use (previously Mac-only) to Windows. The Codex app can now take over the active Windows desktop — moving the pointer, typing, and operating any foreground app the user allows — and can be steered remotely from the ChatGPT mobile app even while the user is away from the machine. This is a new endpoint attack surface on a new OS: a local AI agent that drives the GUI of arbitrary applications (browsers, app settings, data sources with no API) with the logged-in user's full desktop privileges. ENDPOINT must inventory Codex installs that have the Computer Use plugin enabled as distinct desktop-control capabilities per host, capture which apps are allow-listed (including "Always allow" grants that suppress future per-task prompts), and attribute GUI-level actions to the agent rather than the human. New toxic combinations: an "Always allow" grant on a sensitive app (email, finance, admin console) combined with mobile remote control means a prompt-injected or hijacked Codex session can act against that app's UI unattended, with no terminal/CLI trace — Codex's own docs note it can't automate terminal apps or itself, so GUI-driven actions are the bypass path. Source: https://developers.openai.com/codex/windows
- **[ENDPOINT] [MEDIUM] Cursor — Auto-review Run Mode (reduced-approval Shell/MCP/Fetch execution)**: Cursor 3.6 adds a run mode that lets the agent execute Shell, MCP, and Fetch tool calls without per-call human approval. Allowlisted calls run immediately, sandboxable calls run isolated, and the remainder are gated by an AI **classifier subagent** instead of a human. This removes the human from the loop for a large class of tool executions — including arbitrary shell commands and outbound fetches — on the developer endpoint. ENDPOINT (watching tier) should treat Auto-review as a distinct, higher-autonomy execution posture per Cursor install: record whether it is enabled, the configured allowlist of immediately-running Shell/MCP/Fetch operations, and any custom classifier instructions (which themselves become a prompt-injection / policy-weakening target). New toxic combination: a permissive allowlist plus a steerable classifier means an agent can run shell commands, reach MCP servers, and exfiltrate via Fetch with only an LLM — not a person — deciding what is safe. Source: https://cursor.com/changelog/auto-review
