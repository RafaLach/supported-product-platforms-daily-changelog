## New Coverage Required

- **[ENDPOINT] [MEDIUM] OpenAI Codex CLI — OAuth-authenticated MCP servers + per-server environment targeting**: Codex CLI 0.134.0 adds OAuth login flows for MCP servers (server-advertised scopes, configurable callback port/URL) and **per-server environment variable targeting** (`--env KEY=VALUE`, `env_http_headers` pulling values from the environment). This is an extension of the Codex MCP connection surface: a Codex endpoint can now hold OAuth tokens for, and inject distinct secrets/environment into, each connected MCP server. ENDPOINT must inventory MCP servers configured per Codex install as distinct connection entities, capture each server's auth mode (OAuth vs. stdio `--env` secrets) and its scoped environment, and recognize that **read-only MCP tools now execute concurrently** — changing the per-server tool-execution timing model. New toxic combination: a Codex install with an OAuth-authenticated MCP server whose granted scopes exceed the task's need, or a per-server env carrying long-lived credentials. Source: https://developers.openai.com/codex/mcp
- **[AISPM] [MEDIUM] Google Vertex AI — Colab Enterprise Data Science Agent (GA)**: A new code-executing agent entity now generally available inside Colab Enterprise notebooks. It autonomously plans, writes and **runs code**, and drives ML/forecasting and large-scale BigQuery ML / BigQuery DataFrames / Apache Spark jobs against uploaded CSVs or referenced BigQuery tables. AISPM (secondary tier) must add the Data Science Agent as a discoverable agent inventory entity per Colab Enterprise runtime, map its data reach (which BigQuery tables/datasets and uploaded files a given notebook agent can touch), and treat the notebook runtime + its IAM identity as the agent's blast-radius scope. Because the agent executes generated code with the notebook's data-access permissions, a prompt-injection or mis-scoped runtime identity becomes a path to autonomous reads/writes against connected BigQuery data — a new unmonitored data-flow for a secondary-tier platform. Source: https://docs.cloud.google.com/colab/docs/use-data-science-agent
- **[ENDPOINT] [MEDIUM] Cursor — /loop Skill (scheduled unattended agent execution)**: Cursor v3.5 ships a bundled `/loop` skill that re-runs an agent prompt on a recurring local schedule until a target outcome is reached. This breaks the assumption that a Cursor agent only acts when a human is driving it: an agent can now persist and re-execute unattended on the endpoint. ENDPOINT (watching tier) should treat each active loop as a durable scheduled-task inventory entity (interval/cron, target prompt, terminating condition), attribute its repeated tool/command executions to the schedule rather than to a live user session, and flag loops that run privileged actions (deploys, external calls) without a human in the loop. Source: https://cursor.com/docs/skills
